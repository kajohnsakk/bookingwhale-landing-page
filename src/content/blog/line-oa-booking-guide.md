ระบบจองคิวผ่าน LINE OA ช่วยให้ลูกค้าเปิดหน้าจองจากช่องทางที่คุยกับร้านอยู่แล้ว เลือกวัน เวลา และส่งรายละเอียดการจอง ส่วนร้านดูรายการจองและรอบที่เปิดรับได้จากระบบจัดการ บทความนี้อธิบายสิ่งที่ต้องเตรียมและวิธีตรวจสอบก่อนเปิดใช้งาน โดยใช้รูปแบบการจองเป็นรอบวันเวลาเป็นหลัก

## เริ่มจากแยก “จองล่วงหน้า” กับ “คิวหน้าร้าน”

ถ้าลูกค้าต้องเลือกวันและเวลาก่อนมา เช่น จองโต๊ะ คลาสออกกำลังกาย หรือเวลารับบริการ คุณกำลังตั้งระบบนัดหมายล่วงหน้า แต่ถ้าต้องแจกหมายเลขให้ลูกค้าที่มาถึงแล้วและเรียกคิวทีละคน นั่นคือการจัดคิวหน้าร้าน ซึ่งเป็นคนละขั้นตอน

Booking Whale แสดงรูปแบบการรับจองวันเวลาและจำนวนที่รับได้ ดูตัวอย่างที่ [ระบบจองสำหรับธุรกิจ](/#business) หากร้านต้องใช้ทั้งสองแบบ ควรแจ้งขั้นตอนจริงให้ตรวจสอบก่อนเลือกใช้ ไม่ควรถือว่าระบบจองทุกตัวมีการเรียกคิวหน้าร้านด้วย

## 1. เตรียมข้อมูลที่จะใช้เปิดรับจอง

| สิ่งที่ต้องเตรียม | ตัวอย่าง | สิ่งที่ต้องตัดสินใจ |
| --- | --- | --- |
| บริการ | จองโต๊ะมื้อเย็น | ลูกค้าจองอะไร และต้องระบุจำนวนคนหรือไม่ |
| วันและเวลา | ศุกร์–อาทิตย์ 18:00 และ 20:00 | รอบไหนเปิดรับจองออนไลน์ |
| จำนวนที่รับ | คลาสโยคะ 8 คนต่อรอบ | หนึ่งการจองใช้กี่ที่ และร้านรับพร้อมกันได้เท่าไร |
| เวลาทำงาน | บริการ 60 นาที | ต้องเผื่อเวลาเตรียมหรือทำความสะอาดหรือไม่ |
| ช่องทางช่วยเหลือ | LINE OA ของร้าน | ลูกค้าติดต่อใครเมื่ออยากเปลี่ยนหรือยกเลิก |

ตัวอย่างเหล่านี้เป็นข้อมูลจำลองสำหรับวางแผน ควรใช้กำลังรับจริงของร้าน หากมีช่าง ห้อง หรืออุปกรณ์ที่ใช้ร่วมกัน ให้ตรวจสอบว่าระบบรองรับเงื่อนไขนั้นอย่างไรก่อนเปิดหลายบริการพร้อมกัน

## 2. ตั้งรอบและตรวจหน้าจองก่อนนำลิงก์ไปใช้

เริ่มจากบริการที่เข้าใจง่ายหนึ่งรายการ เปิดเฉพาะรอบที่ร้านพร้อมรับ แล้วตรวจชื่อบริการ วันเวลา จำนวนคน และรายละเอียดที่ลูกค้าต้องกรอก

สำหรับร้านอาหาร ลองกำหนดว่าหนึ่งรายการจองหมายถึงหนึ่งโต๊ะหรือจำนวนผู้ใช้บริการ สำหรับคลาส ให้ตรวจว่าจำนวนที่แสดงสัมพันธ์กับที่นั่งในรอบนั้น ส่วนธุรกิจบริการควรตรวจระยะเวลางานและช่วงพักระหว่างลูกค้า ดูรายละเอียดเพิ่มเติมใน [หน้าร้านอาหาร](/businesses/food-beverage/), [หน้าคลาสและกีฬา](/businesses/fitness-sports/) และ [หน้าธุรกิจบริการ](/businesses/services/)

เมื่อได้ลิงก์หน้าจองแล้ว ให้เปิดจากมือถือจริงก่อนเผยแพร่ ตรวจว่าเป็นหน้าร้านที่ถูกต้องและมีช่องทางให้ติดต่อหากจองไม่สำเร็จ

## 3. เพิ่มทางเข้าจองใน LINE OA

Rich Menu ใช้เป็นทางเข้าหน้าจองได้ โดยให้พื้นที่กดของเมนูเปิด URL ที่กำหนด เอกสาร LINE ระบุว่าสามารถตั้ง Rich Menu ผ่าน LINE Official Account Manager หรือ Messaging API ได้ อ่านรายละเอียดจาก [เอกสาร Rich Menu ของ LINE](https://developers.line.biz/en/docs/messaging-api/using-rich-menus/)

สำหรับเจ้าของร้านที่ต้องการให้ลูกค้ากดไปหน้าจอง ควรเริ่มจากเมนูที่มีข้อความชัด เช่น “จองโต๊ะ” หรือ “จองคลาส” แล้วกำหนดลิงก์หน้าจองที่ตรวจสอบไว้ หากมีเมนูเดิมอยู่ ให้จัดตำแหน่งปุ่มจองให้หาเจอโดยไม่บังช่องทางติดต่ออื่น

การใส่ลิงก์ในเมนูไม่ได้ยืนยันว่ามีการส่งข้อความเตือน การเข้าสู่ระบบ หรือการยืนยันจองอัตโนมัติทุกแบบ ฟังก์ชันเหล่านี้ต้องตรวจตามการเชื่อมต่อและข้อเสนอของระบบที่เลือกใช้

## 4. ทดสอบตั้งแต่ลูกค้ากดจนร้านเห็นรายการ

ลองด้วยบัญชีลูกค้าที่ไม่ใช่บัญชีผู้ดูแล และตรวจทีละขั้นตอน:

1. เปิด LINE OA ของร้านและกดปุ่มจอง ตรวจว่าไปหน้าร้านถูกแห่ง
2. เลือกวันที่เปิดบริการ ตรวจว่ารอบปิดไม่ทำให้ลูกค้าเข้าใจว่ายังจองได้
3. เลือกเวลาและจำนวนคน จากนั้นส่งรายละเอียดตามขั้นตอนบนหน้าจอ
4. ตรวจว่ารายการ วันเวลา และจำนวนคนในระบบร้านตรงกับที่ลูกค้าเลือก
5. ลองรอบที่เต็มและการจองพร้อมกัน เพื่อดูว่าจำนวนที่รับถูกควบคุมตามเงื่อนไขจริง
6. ตรวจวิธีเปลี่ยน ยกเลิก และติดต่อร้าน รวมถึงสิ่งที่ต้องให้พนักงานช่วยดำเนินการ

ถ้าร้านยังรับจองทางโทรศัพท์หรือข้อความด้วย ให้กำหนดว่าผู้ใดต้องนำรายการเหล่านั้นมารวมในตาราง เพื่อไม่ให้ช่องทางต่าง ๆ ใช้กำลังรับเดียวกันเกินจำนวน

## 5. เปิดใช้งานและตรวจปัญหาจากการจองจริง

เริ่มจากรอบหรือบริการจำนวนเล็กน้อยที่พนักงานดูแลได้ ให้พนักงานรู้ว่าต้องเปิดดูรายการจากที่ใดและตอบลูกค้าอย่างไรเมื่อข้อมูลไม่ตรงกัน หลังเริ่มใช้งาน ให้จดว่าลูกค้าติดขั้นตอนไหนและมีคำถามใดซ้ำ แล้วปรับคำอธิบายหรือข้อมูลบริการตรงจุดนั้น

ก่อนเลือกแพ็กเกจ ให้ถามเรื่องค่าใช้จ่าย เงื่อนไขทดลองใช้ การเชื่อมต่อ และความสามารถเฉพาะที่ร้านต้องการ เช่น เงินมัดจำ สมาชิก หรือการเลือกพนักงาน โดยอ้างอิงข้อเสนอปัจจุบัน ไม่ใช้ตัวเลขจากบทความเก่าเป็นราคายืนยัน

## คำถามก่อนสร้างระบบจองคิวผ่านไลน์

### ใช้ LINE OA เดิมได้ไหม?

ให้นำข้อมูล LINE OA และรูปแบบเมนูที่ใช้อยู่มาประกอบการตรวจการเชื่อมต่อก่อนเริ่ม ไม่จำเป็นต้องเปลี่ยนช่องทางที่ลูกค้าคุ้นเคยเพียงเพื่อวางแผนระบบใหม่

### ต้องเขียนบอตเองหรือไม่?

การทำปุ่มเปิดลิงก์หน้าจองเป็นคนละเรื่องกับการพัฒนาบอตสนทนา ควรเริ่มจากสิ่งที่ลูกค้าต้องทำจริง หากต้องให้บอตตอบ ตรวจสอบข้อมูล หรือดำเนินการเฉพาะ ให้แยกความต้องการนั้นออกมาประเมินเพิ่มเติม

เหมาะกับการเริ่มพิจารณาระบบสำหรับบริการที่เปิดรับเป็นวันเวลาและกำหนดจำนวนที่รับได้ เช่น โต๊ะอาหาร คลาส และบริการนัดหมาย หากมีทรัพยากรร่วมกันหรือกฎซับซ้อน ให้ตรวจรูปแบบก่อนใช้งาน
